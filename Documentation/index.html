Introduction

Ohmly is a static HTML template for online stores that sell electronics: audio, phones, laptops, wearables, and gaming gear. It gives you the design and front-end behavior of a complete store. It does not include a database, payment processing, or user accounts, so you connect those yourself or through a platform (see Forms).

What's included

  • 24 HTML pages: 3 home layouts, shop (grid, list, full width), product details, cart, checkout, order complete, wishlist, compare, login, register, forgot password, my account, order tracking, about, contact, FAQ, blog, blog details, 404, and coming soon.
  • Compiled CSS (style.css and a minified style.min.css), so you can use the template without installing anything.
  • SCSS source files, organized in small, labeled files, for developers who want to change the design at the source.
  • Vanilla JavaScript (no jQuery) with every feature switchable from one settings block.
  • This documentation and a Licensing folder listing every third-party asset.
Product images are illustrations

The template ships with simple product illustrations (SVG files) so every page looks complete. They are original artwork and you may use them, but most stores replace them with their own product photos (see Changing images).

Installation

What you need

  • A text editor to change files. We recommend Visual Studio Code (free).
  • A web browser such as Chrome, Firefox, Safari, or Edge.
  • For going live: web hosting with cPanel or FTP access.

Option A: View it on your computer

  1. Unzip the file you downloaded from ThemeForest.
  2. Open the HTML folder.
  3. Double-click index.html. It opens in your browser.
Tip: see changes instantly

In VS Code, install the free Live Server extension, open the HTML folder, right-click index.html, and choose Open with Live Server. The page refreshes every time you save a file.

Option B: Upload with cPanel

  1. On your computer, open the HTML folder, select everything inside it, and compress it into a zip file (for example site.zip).
  2. Log in to cPanel and open File Manager.
  3. Open the public_html folder. This is your website's main folder.
  4. Click Upload and choose site.zip. Wait for it to reach 100%.
  5. Back in File Manager, right-click site.zip and choose Extract.
  6. Delete site.zip, then visit your domain. You should see the home page.
Upload the contents, not the folder

If you upload the HTML folder itself, your store will only work at yourdomain.com/HTML/. index.html must sit directly inside public_html.

Option C: Upload with FTP

  1. Install a free FTP program such as FileZilla.
  2. Enter the host, username, password, and port your hosting company gave you, then click Quickconnect.
  3. In the right-hand panel (your server), open public_html.
  4. In the left-hand panel (your computer), open the HTML folder, select everything inside, and drag it to the right-hand panel.

HTML structure

Every page follows the same three-part layout: a header, the main content made of sections, and a footer. Each part is wrapped in comments like <!-- Header Start --> and <!-- Header End -->, so you can always find where a block begins and ends.

Page skeleton

HTML 
<body>
  <!-- Header Start -->
  <header class="site-header">...</header>
  <!-- Header End -->

  <!-- Main Content Start -->
  <main class="main-content">
    <!-- Hero Section Start -->
    <section class="hero">...</section>
    <!-- Hero Section End -->
  </main>
  <!-- Main Content End -->

  <!-- Footer Start -->
  <footer class="site-footer">...</footer>
  <!-- Footer End -->

  <script src="assets/js/main.js"></script>
</body>

Header

HTML 
<!-- Header Start -->
<header class="site-header">
  <div class="top-bar">...Free shipping on orders over $99...</div>
  <div class="site-header__main">
    <div class="container site-header__inner">
      <a class="site-header__logo" href="index.html">
        <img src="assets/images/logo.svg" alt="Ohmly home" width="120" height="32">
      </a>
      <nav class="main-nav" aria-label="Main">...</nav>
      <div class="header-actions">...search, account, wishlist, cart...</div>
    </div>
  </div>
</header>
<!-- Header End -->

Sections

Sections sit inside <main>. To remove a section, delete everything from its Start comment to its End comment. To reuse a section on another page, copy the same block and paste it where you want it.

Footer

HTML 
<!-- Footer Start -->
<footer class="site-footer">
  <div class="container site-footer__grid">
    <div class="footer-widget">...about + social links...</div>
    <div class="footer-widget">...shop links...</div>
    <div class="footer-widget">...help links...</div>
    <div class="footer-widget">...newsletter form...</div>
  </div>
  <div class="site-footer__bottom">&copy; 2026 Ohmly. All rights reserved.</div>
</footer>
<!-- Footer End -->

Customization

The header and footer repeat on every page

Static HTML has no shared "include" files, so the same header and footer code appears in all 24 pages. To change them everywhere at once, use VS Code's search and replace across files: press Ctrl + Shift + H (Cmd + Shift + H on Mac).

Changing the logo

  1. Save your logo as logo.svg (best) or logo.png, about 120 × 32 pixels.
  2. Put it in HTML/assets/images/, replacing the existing file.
  3. If you used a different file name or size, update the src, width, and height in the header of every page, and change alt to your store's name.

Changing colors

All colors live in one place. Choose the method that suits you.

Easy method (no tools): open HTML/assets/css/style.css. The first rule is :root. Change the color codes there and save.

CSS 
:root {
  --color-bg: #F4F5F7;        /* page background */
  --color-surface: #FFFFFF;   /* cards, header */
  --color-text: #16181D;      /* headings and text */
  --color-muted: #5B616E;     /* secondary text */
  --color-border: #DADDE3;    /* lines and borders */
  --color-primary: #2B4EFF;   /* buttons and links */
}
VariableDefaultUsed for
--color-bg#F4F5F7Page background
--color-surface#FFFFFFCards, header, drawers
--color-text#16181DHeadings and body text
--color-muted#5B616ELabels, secondary text
--color-border#DADDE3Borders and dividers
--color-primary#2B4EFFButtons, links, selected states
Keep text readable

White text sits on your primary color, so pick a primary that is dark enough. You can check any pair of colors with the free WebAIM Contrast Checker; aim for at least 4.5:1.

Developer method (SCSS): change the same values in HTML/scss/abstracts/_variables.scss, then recompile (see Recompiling SCSS).

Pick one method

Recompiling SCSS rebuilds style.css from scratch, which erases anything you edited directly in style.css. If you plan to use SCSS, make all your changes in the SCSS files.

Changing fonts

  1. Pick a font on Google Fonts and copy its <link> code.
  2. In the <head> of every page, replace the existing Google Fonts <link> with yours.
  3. In style.css, change --font-body to the new font name, keeping the fallback fonts after it:
CSS 
--font-body: "Your Font", system-ui, -apple-system, sans-serif;

Changing menu items

The main menu is inside <nav class="main-nav"> in the header. Each link is one list item:

HTML 
<nav class="main-nav" aria-label="Main">
  <ul class="main-nav__list">
    <li class="main-nav__item"><a class="main-nav__link" href="blog.html">Blog</a></li>
    <li class="main-nav__item"><a class="main-nav__link" href="contact.html">Contact</a></li>
    <!-- Add a new item: copy a line and change the link and text -->
  </ul>
</nav>

Items with a dropdown (Home, Shop, Pages) contain a <ul class="dropdown"> or <div class="mega-menu"> list; edit the links inside it the same way. The mobile menu copies these links automatically, so you only edit them once per page.

Changing images

The simplest way is to replace a placeholder with your own image using the same file name. The page will pick it up without any code changes. For best results, use these sizes:

ImageFolderRecommended size
Product photoassets/images/products/800 × 800 px, square
Home hero productassets/images/hero/1200 × 900 px, transparent PNG or WebP
Category iconassets/images/categories/400 × 400 px
Blog coverassets/images/blog/1200 × 750 px
Brand logosassets/images/brands/SVG, or PNG 240 × 80 px

The included images are .svg files. If your photo is a .jpg, .png or .webp, or uses a new file name, update the image's src. Always describe the image in alt (for example alt="Black wireless headphones"), because screen readers and search engines use it.

Editing product cards

HTML 
<!-- Product Card Start -->
<article class="product-card">
  <a class="product-card__media" href="product-details.html">
    <img src="assets/images/products/headphones.svg" alt="Aero Wireless Headphones" width="400" height="400">
    <span class="badge badge--sale">-20%</span>  <!-- delete this line for no badge -->
  </a>
  <div class="product-card__body">
    <h3 class="product-card__title">
      <a href="product-details.html">Aero Wireless Headphones</a>
    </h3>
    <dl class="spec-list">
      <div><dt>Battery</dt><dd>30 h</dd></div>
      <div><dt>Weight</dt><dd>250 g</dd></div>
    </dl>
    <div class="product-card__footer">
      <p class="price price--sale"><ins class="price__now">$119</ins><del class="price__was">$149</del></p>
      <button class="btn btn--primary" type="button" data-add-to-cart>Add to cart</button>
    </div>
  </div>
</article>
<!-- Product Card End -->
  • Add a product: copy one whole card (Start to End comment) and paste it next to the others.
  • Specs: each <div> inside spec-list is one row. Two or three rows fit best.
  • No discount: remove the <del> old price and the sale badge.
  • Badge styles: badge--sale, badge--new, badge--stock.

Recompiling SCSS (optional, for developers)

You only need this if you edit files in the scss folder.

  1. Install Node.js (the LTS version).
  2. Open a terminal in the main template folder (the one containing package.json). In VS Code: Terminal → New Terminal.
  3. Run these commands:
Terminal 
npm install         # once, downloads the Sass compiler
npm run build       # rebuilds style.css and style.min.css
npm run watch       # rebuilds automatically every time you save

JavaScript features

All features are in HTML/assets/js/main.js. The top of that file has a settings block. Change true to false to turn a feature off across the whole site.

JavaScript 
const SETTINGS = {
  preloader: true,          // loading screen on page load
  stickyHeader: true,       // header stays visible when scrolling
  newsletterPopup: true,    // shows once per visitor
  newsletterDelay: 5000,    // milliseconds before the popup appears
  quickView: true,          // "Quick view" modal on product cards
  backToTop: true,          // arrow button at bottom right
  countdown: true           // deal timers
};

Setting a countdown date

Each timer reads its end date from the data-countdown attribute. Use the format YYYY-MM-DDTHH:MM:SS:

HTML 
<div class="countdown" data-countdown="2026-12-31T23:59:59">Ends December 31</div>

For an always-running demo timer, use a number of days instead, such as data-countdown="+3d". It counts down from 3 days each time the page loads. When a fixed date passes, the timer shows "This deal has ended". The text inside the tag is shown if JavaScript is off.

Filters and cart are visual only

Shop filters, the cart, and the wishlist show how these features look and feel. They do not filter real products or remember items between pages, because that needs a store backend.

Forms

Forms do not send anything by default

The contact, newsletter, login, register, and checkout forms check what the visitor typed and show error or success messages, but they do not send emails, store data, or take payments. This is normal for HTML templates.

Making the contact and newsletter forms work

The easiest way is a form service. Sign up with one (for example Formspree, or Netlify Forms if you host on Netlify), then set the form's action to the address they give you:

HTML 
<form class="contact-form" action="https://formspree.io/f/your-form-id" method="POST" data-validate>
  ...
</form>

Many demo forms have a data-success="..." attribute. It shows that message instead of sending the form. Delete data-success when you connect a real form service, otherwise the form will never be sent. On the register page, data-match="#reg-password" checks that both passwords are the same; you can use it on any field.

For newsletters, most email marketing services (such as Mailchimp) provide an embed form action URL you can paste the same way. These services have their own pricing and terms.

Login, accounts, cart, and checkout

These need a backend: a platform such as Shopify or WooCommerce, or custom code in a framework such as Laravel or Node.js. A developer can use these HTML pages as the design and connect them to that backend.
